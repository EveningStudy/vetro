## Local corpus

Run from the repository root with Cargo on `PATH`. Capture reads the local stores and writes `.orchestra/corpus/`. Move the existing corpus entries within that ignored directory before recapturing to preserve hand-edited expectations.

```powershell
cargo test -p vetro-core --all-features --lib capture_native_corpus -- --ignored --nocapture
cargo test -p vetro-core --all-features --lib check_native_corpus -- --ignored --nocapture
```

An ignored core test can use the production index and history readers directly and keeps the corpus tooling out of shipped executables. The check uses a temporary Vetro home under the corpus and an offline Python 3 ACP endpoint. The endpoint answers initialize, list, load, and close from local files. Recorded ACP traffic uses an isolated index so a replay of a native session cannot introduce a second parent candidate. Workspace stdin resolution is disabled during corpus indexing.

Capture samples recent bounded files and SQLite rows. It selects Claude desktop metadata tails and Vetro origins, Codex state and rollout pairs, Devin saved chains, Antigravity step databases, Kiro metadata and message JSONL, and any completed ACP load sequence in the local Vetro wire logs. To prioritize a particular Devin history, set `VETRO_CORPUS_DEVIN_SESSION` to its native ID in the capture process. Codex rollout paths are resolved against the copied files. Foreign SQLite reads use Vetro's read-only VFS with `mode=ro`. Capture can find stores even if their runtime is unavailable. Kiro catalog entries come from `session.json` when ACP wire data is unavailable.

Edit `.orchestra/corpus/expectations.json` directly. `created_in_vetro` contains the sampled IDs whose origin is preserved in Vetro. Each entry under `threads` uses the `agent:nativeId` key, a human-readable `case` label, and a map of `checks`. Set `absent: true` for a session expected to be absent from the index. Capture seeds expectations from native fields and pairs the reported Devin receipts using the shell handle, session marker, and native start time. Review those expectations when updating the corpus.

Supported checks include `source`, `internal`, `createdAt`, `activityTime`, `defaultRoot`, `indexed`, `parent`, `parentHasToolCall`, `parentToolCallId`, `parentConfidence`, `parentToolListsChild`, `copyPerAnswer`, `hasCopyableAnswer`, and `nativeTurnDurations`. Times are epoch milliseconds. Copy checks measure eligibility from indexed timeline items and do not operate the browser or clipboard. The result table shows case labels and field names, with raw values and IDs kept in the local expectations file.

Default workspace tests consume synthetic Claude JSONL and rate limits, Codex state rows and rollout events, Devin SQLite rows, Kiro session and turn records, Antigravity protobuf fields, and ACP replay frames. Keep real records and owner-specific expectations under `.orchestra/corpus/`.
