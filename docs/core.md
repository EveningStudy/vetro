# Core and CLI

`vetro serve` binds to `127.0.0.1`. It prints the URL with a fragment for local authentication. A zero port in `config.json` selects port 47600 or the next available port. `--port` overrides `config.json`, `--port 0` requests an ephemeral port, and `--open` opens the URL in the default browser. The core embeds `apps/web/dist` if it exists at build time. `VETRO_WEB_DIR` can point at a different UI directory for development.

The binary forwards the `claude`, `codex`, `acp`, and `antigravity-store` features to `vetro-core`. They default to off. Build the binary with `cargo build -p vetro-cli --features claude,codex,acp` to register the built-in agents and configured ACP commands. Add `antigravity-store` to merge the desktop and CLI conversation stores with Antigravity's ACP list and prefer disk transcripts when available. `registry::built_ins` is the adapter wiring point. A caller can use `Registry::new` with its own adapters and pass the registry to `Core::new`. The desktop shell can bind a `Server`, get its `local_url`, and await `serve` with a shutdown signal.

- `home` owns configuration, local overlays and thread choices, versioned option caches, hashed local and paired-device sessions, and logs. Each raw log is a bounded per-thread snapshot named with the SHA-256 of its thread ID. Multiplexed adapters retain the process launch and initialization exchange alongside the thread's traffic.
- `sessions` keeps live timelines and sequence numbers, queues prompts when steering is unavailable, reapplies explicit choices on resume, and preserves pending requests during idle maintenance. Warm processes are released after about a minute without live work. The configured idle limit applies to live sessions and signed-in Devin processes.
- `storage` maintains the disposable SQLite index at `index.db`. It stores summaries, per-source sync marks, searchable text with CJK tokenization, and cross-agent links with confidence tiers. `history` watches native file stores and polls protocol stores in the background. An open historical thread can receive new items through its existing subscription.
- `server` serves HTTP and WebSocket RPC on loopback. Local session cookies survive restart. Optional remote access uses paired devices and a dedicated Tailscale Serve HTTPS entry on port 8443. Vetro cleans up its own entry on disable or shutdown. The server runs WebSocket requests concurrently after `app.hello` and signals clients to refresh if they fall behind.
- `vetro agents` prints detection results. `vetro threads` supports `--search` and `--children-of`. `vetro links` prints discovered links and confidence. `vetro show <thread-id> [--limit N]` prints the newest stored items. `vetro probe` sends one prompt, handles interactions, and can print the wire log with `--raw`. Both `show` and `probe` support `--auth [METHOD]`. `--yes` on `probe` selects an offered allow-once option.

Changes to adapter launch configuration take effect on restart. All built-in adapters accept configured binary paths, extra arguments, and environment overrides.
